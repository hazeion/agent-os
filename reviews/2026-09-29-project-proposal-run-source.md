The migration derives the replacement table, its self-FKs, indexes and triggers from the checked-in exact schema-40 object graph. It creates `mentat_runs_next`, temporarily removes only the captured Run-owned triggers, then copies and removes old Run rows in bounded ID-ordered batches inside one guarded transaction with foreign keys disabled. It drops the now-empty old table, renames the new table to `mentat_runs`, then recreates every Run-owned index and trigger (including identity and attention triggers). Any failure rolls back the rows and triggers together. It must not rename the old table first, which would rewrite dependent references.
