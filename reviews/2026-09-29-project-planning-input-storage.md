# Owner-prepared Project planning input storage

Status: implementation scope for the next Project proposal foundation slice after the owner-selected lead role. This record narrows storage only; it grants no proposal Run, generated-output admission, or owner Apply capability. The reviewed end-to-end boundary remains `reviews/2026-09-29-project-lead-proposals.md`.

Schema 39 adds immutable owner-private Project planning-input versions tied to the existing live Project incarnation, exact current Project context version, exact selected lead role version ID/revision and canonical Agent ID/incarnation/registry revision, runtime-binding digest, and active context grant revision. Historical rows must match the retained immutable role version, and future admission must recheck the current role. It stores one owner-reviewed instruction brief and a bounded ordered selection of context files. Each selected file freezes its attachment ID, content digest, type and byte count; at most eight files and one image are allowed, and the total retained selection cannot silently truncate. The Project/context/Agent/grant/role must be revalidated on later admission, not inferred from this saved row. A new Project using the same display ID cannot inherit an old input.

Generated output selection is deliberately unavailable in this storage slice because no canonical registered-output authority exists yet. The later generated-output registration slice must add an exact migration and source-Run/blob pin graph before any such output can be selected. Task-input versions are separate and must never be reinterpreted as Project planning inputs.

Existing schema-38 roots upgrade only through the exact predecessor-schema gate. Format-4 private backup/restore must validate the new graph, its bounded metadata and referenced blobs, including retained context-file pinning. Schema-5 compatible-root export must omit schema-39 tables and leave the authoritative source unchanged. Schema-39 adds a justified shared metadata-budget increment; publication must charge its prospective complete graph before commit so every admitted version remains backup-valid. A context version referenced by an input cannot be pruned while the input remains retained. The storage is capped at 256 versions overall and 32 per Project incarnation. Invalid or orphaned rows, type/byte drift, duplicate ordinals, digest mismatch, ID reuse, and unsupported source kinds fail closed. A restore preserves historical evidence but revokes context grants; it cannot make an old input eligible for a Run.

This slice includes schema, validator, private backup accounting, and focused migration/restore/tamper/retention tests. There is no browser write route, runtime adapter call, Run source, Agent proposal intake, or Task mutation. A later owner editor must implement exact revisions and guarded publication; a later qualified Linux runtime slice must implement fixed proposal-only admission and receipt before any Run starts. Two independent read-only code reviews and relevant regression checks precede a full PR.
